# QNH Cockpit

Internal dashboard of QNH GmbH (owner: Christoph Umbricht) for all its apps. Talk to Christoph in **German** (Swiss usage, "ss" instead of "ß"); he is a pilot, not a programmer. UI text German; code, comments and commit messages English.

## How it works

- Vite + vanilla JS, static web app (no server of its own). `npm run dev` (port 5185), `npm run build`, `npm test`.
- Per app, the cockpit signs in to that app's **own Supabase project** with Christoph's normal app account (6-digit e-mail code, `shouldCreateUser: false`). Sessions are stored per app (`storageKey: qnh-cockpit-<app>`).
- All data comes from the app's **admin functions**, which check `is_admin()` in the database. The cockpit only knows public URLs and anon keys (`.env`, see `.env.example`). **Never add a service_role / secret key** — the cockpit runs in the browser.
- `?demo` in the URL shows invented sample data (`src/demo.js`) without signing in — use it for layout work and screenshots.

| File | Role |
|---|---|
| `src/apps.js` | list of apps, overview tiles per app (`stats` → keys of `admin_stats()`), tabs |
| `src/api.js` | Supabase clients per app, auth, admin calls |
| `src/main.js` | state, rendering (template strings, always `esc()` user data), events |
| `src/format.js` | pure helpers, unit-tested in `tests/` |

**Layout:** desktop sidebar = Heute · Aufgaben (the roadmap, `#roadmap`) · Finanzen, then «Apps», then «Social» with one sub-link per channel (`#social/<appId>` sets the Social filter), Hangar at the bottom. Phone (≤ 860px): bottom bar Heute · Aufgaben · Apps (`#apps`) · Social · Finanzen (items marked `desk-only` / `phone-only`); Hangar, search, theme, refresh, sign-out sit in the menu sheet behind the initials; the round + (`S.sheet = "new"`) adds a task, a bill, a post or a package from anywhere. Sheets make `.shell` inert and keep the focus. «Heute»: date + calendar week, four instruments, lanes, side column «Als Nächstes» / «Diese Woche auf Sendung» / «Geld».

## Social packages → cockpit (automatic)

`npm.cmd run social` (status) / `npm.cmd run social -- import [folder…]`: reads `pakete/<folder>/` (format `docs/social-paket.md`, same parser and checks as the cockpit), uploads to bucket `social-media` and inserts DRAFTS with `scheduled_at` = `suggested_time` (session from `scripts/qnh-session.mjs`). State in `pakete/.imported.json` (folder → post id, content hash, updated_at). Changed packages update the draft only if it is still draft/failed and unedited in the cockpit; deleted posts are not re-created; hand-imported twins are linked by caption. Logic in `scripts/social-lib.mjs`, tests `tests/social-import.test.mjs`. **Whenever packages were added or re-rendered, run the import and tell Christoph which drafts wait in Social → «Freigabe-Runde».** Windows task «QNH Social-Import» runs `scripts/social-import-task.ps1` daily 07:30 + at logon (log `pakete/.import.log`). Never approve or publish. Optional `todo` (hand work in the Instagram app; column from `20261014120000_social_todo.sql`, editable in every status – the guard lets a todo-only update through even after publishing) is added to existing posts only where they have none yet.

## «Heute» and Finanzen

«Heute» (`todayView` in `src/main.js`) is ONE list in three lanes (`src/today.js`, tested): **Jetzt** (overdue/broken), **Heute**, **Diese Woche**. Items come from `agenda()` in main.js: app alerts (`todos`), store, `socialItems`, `qnh.agenda` (roadmap due dates; «Erledigt» rolls recurring items forward via `recurringDone`/`nextDue` – also from the edit form, unless «einmalig» is chosen in the same save – «Morgen» sets `snoozed_until`), `finance.agenda` (lanes from `financeLane` in calc.js: bills by due date – without one 30 days after `created_at`, labelled «Fälligkeit geschätzt»; renewal reminders by when the reminder starts: started → Heute, within 7 days → Diese Woche; they count in the header and the Finanzen badge). Recurring dates keep `roadmap_items.repeat_day` (day of month from the due date chosen in the editor; 31 = month end), so 31.3. → 30.6. → 30.9. → 31.12. without drift. New sources: return `{ key, lane, tone, title, sub, where, scope, href, date, actions }`.
Finanzen (`#finanzen`, `src/finance/`): migration `20261021100000_finance.sql` (`fin_costs` incl. `ack_until` = «Behalten» up to that renewal date, stored in the DB, not the browser; `fin_bills`, private bucket `finance`, roadmap `repeat`/`repeat_day`/`snoozed_until`/`last_done_at`). `qrbill.js` parses Swiss QR-bills (SPC 02xx, IBAN mod 97, QRR mod 10, bill info /10/ /11/ /40/ with `\/` `\\` escapes); it throws `QrBillError` only when the code is unusable and returns German `warnings` otherwise (IBAN not CH/LI, QR-IBAN ↔ QRR mismatch, SCOR mod 97, currency not CHF/EUR, amount 0.00, broken /11/ date, due date in the past, untyped reference > 40). `reader.js` reads the QR from PDF (pdf.js **legacy** build – the modern one needs JS that Safari lacks; scanned PDFs need the decoders in `pdfjs-wasm/`, served by the `qnh-pdfjs-wasm` plugin in `vite.config.js` and passed as `wasmUrl`) or photo (jsQR), loaded lazily; `calc.js` (renewals from the anchor date, «Nächste 30 Tage» without double-counting a renewal whose bill is entered, monthly totals per currency – no exchange rates, CSV). Bills: the row is saved first, then the file is uploaded and linked (replacing deletes the old file; only pdf/jpeg/png/heic/heif/webp like the bucket). The CSV export loads ALL bills of the chosen period (`exportBills`, paged; paid → Swiss paid day, else due date). Paying stays in e-banking; never store card numbers. Docs: `docs/finanzen.md`.
**Paid privately / Vorgründung:** migration `20261021120000_finance_private.sql` (`fin_bills.paid_by` firma|privat, `reimbursed_at`, `net`, `vat`, `paid_with`; a receipt (payee + number) only once). «Offen an Christoph» = privat and not reimbursed (`owedPrivately` in calc.js), section with «Zurückbezahlt ✓». Import from the local Ablage: `npm.cmd run finanzen -- import "<…>\ausgaben.json" [--dry]` (`scripts/finanzen.mjs`, logic + format in `scripts/finanzen-lib.mjs`, tests `tests/finanzen-import.test.mjs`; uploads the receipt files to bucket `finance`, creates Abos from `recurring`/`renews`/«(bis …)», safe to run again), `npm.cmd run finanzen -- offen`. **Real amounts, receipt numbers and PDFs never go into git** – they live in QNH Core and in `C:\QNH\04_Finanzen` (not in the repo).
